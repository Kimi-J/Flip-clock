1总体架构

这个项目最核心的架构特点：一个二进制、六种运行身份、四类窗口家族，全部共享同一份前端产物和同一个 WebView2 数据目录。

应用只有一个 app.exe。启动时 Rust 端解析命令行参数决定运行模式（Windows 屏保协议）：

命令行模式行为窗口
（无）normal普通桌面时钟，抑制系统屏保normal-N（每选中显示器一个全屏窗）或 widget-N（小窗形态）
/ssaver屏保运行态，任意输入退出saver-0..n（所有显示器各一个置顶全屏窗）
/cconfig配置模式，直接退出无（配置由主应用设置面板处理）
/ppreview预览模式，直接退出无（WebView2 无法 SetParent 嵌入外部 HWND）
为什么这套架构成立 屏保本质上就是改了后缀的 exe（fs::copy(exe, FlipClock.scr)），所以主程序和屏保天然共享同一份代码与前端资源；窗口身份靠 label 前缀 区分（normal-/saver-/widget-/wmenu-），Rust 端的事件钩子（落盘、矫正、记账清理）用前缀精确匹配，互不干扰；前端身份靠 Rust 在 WebView 创建前用 initialization_script 注入 window.__LAUNCH_MODE__，页面 JS 第一行就能读到，避免 URL 重载导致的帧率下降。

2.3 时间对齐：setTimeout + rAF 的组合

const tick = () => {
  const now = new Date();
  setTime(split(now, is24Hour));
  const ms = now.getMilliseconds();
  timer = window.setTimeout(() => { raf = requestAnimationFrame(tick); }, 1000 - ms);
};

不是简单的 setInterval(1000)：每次计算距下一个秒边界的剩余毫秒数再定时，消除累积漂移；套一层 requestAnimationFrame 让状态更新对齐渲染帧，翻页动画起始帧不撕裂。

2.4 主题系统：CSS 变量 + data-theme 属性

10 套主题全部通过 html[data-theme="xxx"] 切换一组 CSS 变量（--card-from/to、--digit、--seam、--bg-from/via/to、--accent 等），组件代码零分支。特殊主题用属性选择器做增量覆盖：voxel（像素界）覆盖字体为 Press Start 2P 并把卡片尺寸改为 px 绝对单位（字号缩小但卡片不变）；noir/pure（极简黑白）用 clip-path 给卡片接缝处切出瓶颈凹口。

3.2 线程模型：血泪换来的三条铁律

铁律一：build() 绝不能在主线程同步执行 Windows 上主线程同步调用 WebviewWindowBuilder::build() 会与 WebView2 初始化互等死锁（wry#583，Tauri 官方文档明确警告）。所有运行时建窗/改窗命令一律 async fn + tauri::async_runtime::spawn 派发。唯一例外：启动路径（setup 回调，事件循环启动前）同步执行是安全的。
铁律二：绝不对已存在的全屏窗口做状态切换 对已存在窗口调 set_fullscreen/set_position 曾导致主线程与后台线程在窗口内部状态上互等、整进程卡死。显示器几何变化、形态切换一律关旧建新。
铁律三：先建后关 Tauri 默认「最后一个窗口关闭 = 进程退出」。若先关旧窗再建新窗，中间瞬间窗口数为零会直接退出。所以形态切换、reconcile 清理都遵守「先建新、建成功再关旧」。

3.3 可观测性：给「闪退无痕迹」问题上的三道保险

  • panic hook：发布版无控制台，不挂钩子则 Rust panic 完全不可见；挂钩后写入 flipclock.log。
  • SetUnhandledExceptionFilter：访问违例/栈溢出/堆损坏这类硬崩溃不走 Rust panic 机制，此前表现为「日志戛然而止」。过滤器在进程咽气前写下异常码 + 地址（如 0xC0000005 ACCESS_VIOLATION）。
  • MAIN 线程标记 + 序列号：每条日志标注发出线程；卡死排查方法——找到最后一条 MAIN 日志即主线程卡住的位置。

4卡片翻页动画的具体实现

这是本项目最有辨识度的部分：单叶片、双面、180° 连续翻转（split-flap 的 CSS 还原），而不是常见的「上下两片各转 90°」拼合方案。

4.1 DOM 结构：三明治三层

<span class="flip-unit">              ← perspective: 900px（3D 舞台）
  <span class="flip-static--top">     ← 静态上半卡，显示新值上半（翻转开始瞬间就换新值）
  <span class="flip-static--bottom">  ← 静态下半卡，翻转中显旧值下半，结束才换新值
  <span class="flip-leaf">            ← 翻片（仅 flipping 时存在），绕下边缘转 180°
    <span class="flip-leaf__face--front">  ← 正面：旧值上半
    <span class="flip-leaf__face--back">   ← 背面：新值下半（backface-visibility: hidden）
</span>

4.2 状态机与时序（FlipCard.tsx）

value 变化→ previous = current
current = 新值（上半卡立即换新，被翻片正面遮挡，观众看不见）→ flipping = true
挂载翻片，CSS 动画 0.6s→ 600ms 后 flipping = false
卸载翻片，下半卡换新值

观众视角的完整时序（这是整个动画的精髓）：

阶段旋转角观众看到
前半程0° → 90°翻片正面（旧值上半）遮挡上半卡 → 上半=旧、下半=旧 → 完整旧值
过中线瞬间= 90°翻片侧对观众（edge-on，视觉上是一条线），正面开始背向
后半程90° → 180°上半卡露出新值上半；翻片背面（新值下半）朝向观众覆盖下半卡 → 完整新值
结束移除翻片上下半卡均为新值，静止

4.3 保证「不穿帮」的细节

  • 半卡数字裁切：数字元素高度 = 整卡高（--card-h），line-height 同高（注释明确说明不能用 %，% 相对字号），top 半卡 overflow:hidden 只露数字上半、bottom 贴底只露下半。翻片两面复用同一裁切方式，位置精确重合。
  • 接缝：独立伪元素 .flip-unit::after 叠在中线（3px、主题色 --seam、z-index:15），置于翻片之上，翻转全程遮住上下半卡与翻片的接缝。
  • 背面前置隐藏：backface-visibility: hidden，翻片背面在 0-90° 阶段完全不可见，不会提前泄露新值。
  • 动画时长 = React 定时器时长：CSS 0.6s 与 setTimeout(600) 严格一致，卸载翻片的瞬间动画恰好播完（forwards 停在 180°），不会闪帧。
  • 字体：Anton（窄高无衬线，翻页钟经典款），备选 Bebas Neue / Oswald。

4.4 对比：票根皮肤的里程计式滚动

小窗的票根皮肤故意不用翻页（纸片没有翻页物理感），改用 WipeDigit：旧值上滚渐隐 + 新值自下入位渐显，340ms。位移与透明度是两条独立动画（out 层 0.34s 移动 + 0.22s 淡出，in 层 0.34s 移动 + 0.3s 淡入），保证旧值先隐完、新值后显足，无双实重叠。这是「动画要服从材质隐喻」的一个好例子。

5多显示器的实现方法

5.1 枚举：物理矩形 + 持久身份，两套 API 各取所长

  • 物理坐标：EnumDisplayMonitors + GetMonitorInfoW，拿到每台显示器的物理像素矩形（x/y/w/h）。全屏窗口用 PhysicalPosition/PhysicalSize 定位，混合 DPI 下也能精准落位（逻辑坐标会被 DPI 缩放搞乱）。
  • 持久身份：HMONITOR 和 \\.\DISPLAY1 这类名字会随插拔/主屏切换/驱动变化而变，不能跨会话复用。项目用 EnumDisplayDevicesW 两级枚举拿到 MONITOR\厂商码\实例路径（基于 EDID 的硬件身份）作持久 ID。
历史教训（代码注释里原话记录） 持久身份最初用 QueryDisplayConfig + DisplayConfigGetDeviceInfo 实现，其结构体含 union/LUID，手写 FFI 极易布局错位，实际运行中反复出现堆损坏型随机崩溃（同类操作时崩时不崩）。整体移除后改用 EnumDisplayDevices——DISPLAY_DEVICEW 是纯定长数组，无对齐陷阱。查询失败时退化为 \\.\DISPLAYn 作 ID（功能可用，仅跨会话识别变弱）。

5.2 reconcile：幂等收敛状态机（整个多窗管理的核心）

目标只有一个：「选中且在线」的每台显示器恰好有一个全屏窗口。启动、设置变更、显示器热插拔三种触发源全部收敛到同一个函数：

fn reconcile_inner(app) -> bool {
  // 1. 小窗形态 → 整体挂起（widget- 前缀天然不被触碰）
  // 2. 枚举失败 → 不动任何窗口（绝不能据此关窗）
  // 3. targets = 选中 ∩ 在线；为空回退主屏（再兜底第一块）→ targets 永不为空
  // 4. 逐台对账：记账存在 && 窗口活着 && 显示器矩形未变 → 原样保留
  //             否则 → 关旧建新（新 label 只增不复用）
  // 5. 清理：关闭所有不在新账内的 normal- 窗口（先建后关；新账为空则跳过）
  // 6. emit("monitors-changed") 通知前端刷新设置面板
}
记账快照防自激循环（很精妙） 身份识别只认记账（显示器 ID → 窗口 label + 建窗时的显示器矩形快照），绝不依赖窗口自身几何——全屏窗口矩形存在系统性偏差，曾因此每轮误判「漂移」引发关窗/建窗死循环。快照比较的是「显示器矩形 vs 显示器矩形」：只有真实分辨率/位置变化才触发重建，重建后快照更新，数学上不可能自激。另外 reconcile 有 AtomicBool BUSY 防重入 + catch_unwind 兜底，单次故障不拖垮进程。

5.3 热插拔监听：为什么是「隐藏顶层窗口」而不是 message-only

独立线程创建一个隐藏窗口接收 WM_DISPLAYCHANGE 广播。代码注释专门记录：不能用 message-only 窗口（HWND_MESSAGE），它不接收系统广播消息。收到消息后不立即处理——睡眠唤醒/拔插瞬间拓扑会连续抖动，用 SetTimer 做 300ms 防抖，等稳定后再经 async_runtime::spawn 派发 reconcile（遵守铁律一）。

5.4 两种多窗策略的差异

normal 模式saver 屏保模式
窗口数量用户「选中且在线」的显示器（可配置，含离线项保留——重连自动恢复，docking 体验）所有显示器（不遵循显示位置设置）
窗口属性可 resize、进 fullscreenalways_on_top + 不可 resize（屏保安全）

6屏保和主程序共享 GPU 缓存的逻辑

6.1 注册链路

设置面板开启屏保→ fs::copy(app.exe → FlipClock.scr)（exe 同级目录）→ HKCU\Control Panel\Desktop 写 SCRNSAVE.EXE + ScreenSaveActive=1→ 等待时间经 SystemParametersInfoW 与系统双向同步

注册失败有精细的差异化诊断：写 SCRNSAVE.EXE 被拒时，先写一个测试值再删掉——测试值可写说明仅 SCRNSAVE.EXE 被 GPO/杀软保护，不可写说明整个子键无权限，两种情况给完全不同的提示文案。

6.2 共享 data directory：一行配置，两个效果

所有窗口创建时都指定同一个 WebView2 用户数据目录：

fn webview_data_dir() -> PathBuf {
    %LOCALAPPDATA%\com.flipclock.app\webview-data
}
// 每个 WebviewWindowBuilder 都加：
builder = builder.data_directory(webview_data_dir());

这带来两个后果，一好一坏，项目对两个都做了处理：

机制结果
好处app.exe 与 FlipClock.scr 是同一二进制、指向同一数据目录，WebView2 的 GPU 着色器缓存、代码缓存、字体缓存全部互通屏保冷启动速度与帧率和手动开启主程序一致，不会每次触发屏保都经历「冷 WebView 初始化」
坏处WebView2 的同一用户数据目录同时只允许一个进程使用若主程序常驻时系统屏保触发 .scr，.scr 的 WebView 初始化失败，残留一个全屏置顶黑窗——无法操作无法退出的「假屏保」

6.3 对「坏处」的两道防线

防线一：主程序抑制系统屏保 normal 模式 setup 阶段调用一次 SetThreadExecutionState(ES_CONTINUOUS | ES_DISPLAY_REQUIRED)——声明「本线程在持续显示内容」，禁止息屏与系统屏保。主程序本身就是全屏时钟（用户要的正是常显），系统屏保没有存在的必要；进程退出后抑制自动解除，系统屏保恢复正常。这从根上避免了 .scr 与主程序争抢数据目录。
防线二：tauri-plugin-single-instance 单实例 二次启动（比如手动双击 .scr 或 exe）不再新建进程，而是聚焦已有窗口后新实例退出——同样是为了防多进程争抢共享数据目录。

整体逻辑闭环：常驻时主程序自己就是「屏保」（抑制系统屏保）→ 用户离开但主程序没开时，系统屏保触发 .scr → .scr 独占数据目录，还能吃到主程序留下的 GPU 缓存 → 任意输入退出。数据目录是「缓存共享」和「进程互斥」的一体两面，这是 Tauri/WebView2 桌面应用做屏保功能时最值得记住的一条经验。

7小窗形态的实现

7.1 窗口属性：透明三件套 + 前缀隔离

WebviewWindowBuilder::new(app, "widget-N", WebviewUrl::App("index.html"))
  .decorations(false)      // 无边框
  .transparent(true)       // 透明（异形轮廓的前提）
  .shadow(false)           // 关原生阴影：Windows 原生阴影是矩形，圆角/异形处渗色
  .always_on_top(true)     // 置顶
  .skip_taskbar(true)      // 不占任务栏
  .initialization_script("window.__LAUNCH_MODE__ = 'widget';")
  • 投影改由前端 CSS drop-shadow 绘制，且范围必须小于窗口四边 20px 留白（留白不够会渗出窗口被裁）。
  • widget- 前缀让 Rust 事件钩子只对小窗做 Moved/Resized 落盘与长宽比矫正；reconcile 只认 normal-，小窗模式下全屏管理天然挂起。
  • 防暗闪：index.html 里一段内联脚本在样式表生效前给 <html> 打 widget-boot 类强制全程透明——否则样式表底色会在 React 挂载前先绘制，透明窗口闪一块深色矩形。

皮肤决定窗口几何（Rust SkinGeom：基准尺寸/长宽比/min/max）和票面视觉（前端 CSS），两端的几何常量必须同值（前端 SKIN_BASE/SKIN_LIMITS 镜像）。当前两套：

机械台钟 mecha304×156304:156复用 FlipCardGroup 翻页（perspective 9em）拉丝金属机身、近黑内凹卡仓、贯穿中缝铰链轴（压在翻片之上）、四角沉头螺丝（一字槽角度各异）、氖管冒号 1Hz 呼吸

换肤流程：前端 store（权威方）→ set_widget_skin 命令 → settings.json 落盘 + Rust 内存缓存更新 → 皮肤真变化时已存在小窗 set_size(LogicalSize) 复位新默认尺寸（DPI 安全，位置不动）；未变化则幂等 no-op（前端挂载也会调它做自愈同步，不能重置用户保存的缩放）。

7.3 拖拽：为什么不用原生 startDragging

Windows 原生拖动会把窗口「标题栏」钳制在屏幕顶边之内（无标题栏也受限），且会吞掉本次点击。改为手动实现：

  • setPointerCapture 捕获指针——移出窗口边界后仍持续收到 move 事件（拖到屏幕边缘不断线）。
  • 起点记录 screenX/Y（DIP）+ 窗口物理位置 + dpr，移动时 setPosition(物理坐标)，任意方向无限制。
  • 4px 位移阈值：阈值内松手仍算点击，双击回全屏 / 右键菜单的语义得以保留。
  • 每帧从起点绝对值换算，无累积漂移。

7.4 缩放：中心固定 + 对角线投影（v2 重写的关键算法）

原生 startResizeDragging 被弃用，原因有二：① NW/SW 方向缩放时 Windows 只锚定右下角，而 Rust 侧 Resized 长宽比矫正的 set_size 以左上为锚，两个锚点互相拉扯→右下角漂移；② 斜向拖拽偏离对角线时原生尺寸与矫正值反复拉锯→闪烁。手动实现：

// 拖拽位移 (lx, ly) 在"手柄向外对角线 (hx·W, hy·H)"上的投影系数 t：
const t = (lx * hx * g.w + ly * hy * g.h) / (g.w * g.w + g.h * g.h);
// 角点位移 t·(W,H)，中心固定 → 宽高各增 2t·(W,H)（两侧对称）
const newW = clamp(r.ww + 2 * t * g.w * dpr, minW·dpr, maxW·dpr);
const newH = newW * g.h / g.w;            // 长宽比 JS 侧先行锁定
setPosition(cx - newW/2, cy - newH/2);    // 中心恒定
setSize(newW, newH);

Rust 侧的 enforce_aspect 退化为差值 ≤1px 的安全网（矫正自身会再触发 Resized，但那时差值为 0，天然收敛不自激）。三手柄（nw/sw/se）行为统一，皮肤随窗口整体 transform: scale() 等比缩放，布局零改动。

capabilities 权限坑 Tauri v2 权限逐项鉴权，setSize 未在 capabilities 里授权时被静默拒绝（catch 吞错）——现象是窗口只平移不缩放，排查极难。需补 core:window:allow-set-size。

7.5 弹出菜单：为什么必须是独立窗口

菜单内容可能比小窗本身还大，且必须能超出小窗边界显示——单窗口内容无法越界是 OS 硬限制。所以菜单做成独立置顶小窗（wmenu- 前缀）：

  • 前缀特意不匹配 widget-，避免被当作小窗本体误触发落盘与矫正钩子。
  • Rust 端 open_widget_menu 按 dpr 换算菜单物理尺寸，钳制在含点显示器内（防止弹出越屏）。
  • 失焦（点击菜单外任意处）/ Esc / 点击四周留白 → 自关；「回到全屏」先落命令再自关（窗口销毁会中断未完成的 invoke）。
  • 菜单窗固定本地字体栈：新 WebView 首帧 webfont 未激活时 ·/空格宽度随字体重排（FOUT），观感上「皮肤 · xxx」反复闪变——本地字体首帧即最终帧。

7.6 持久化：物理坐标 + 校验 + 兜底

  • 位置/尺寸存 Rust 侧 settings.json（物理像素，与显示器坐标系同体系，混合 DPI 无歧义）。
  • Moved/Resized 事件 500ms 节流落盘（共用一个节流阀），退出时 save_now 兜底（节流可能漏掉拖拽终点）。
  • 启动时校验可见性：窗口左上角 +24px 必须落在某台显示器内，否则视为不可见，回退主屏右下角（留出任务栏高度）。
  • 形态切换（全屏↔小窗）遵守「先建后关」：小窗建不出来保留全屏窗，全屏 reconcile 不出窗口保留小窗，避免零窗口即进程退出。
